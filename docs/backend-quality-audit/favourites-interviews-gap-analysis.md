## Details of what was built

- **Counts.** `upcoming` = open sessions (REQUESTED, CONFIRMED, RESCHEDULE_PROPOSED); `past` = closed (DECLINED, CANCELLED, COMPLETED); `total` = all of the customer's sessions. They cover the customer's full history and ignore page, `status`, `type` and `scope`; `meta.total` is the size of the filtered list. Cancelled and declined are never upcoming. An open session whose time has passed is still `upcoming` until someone completes or cancels it (there is no "expired" state).
- **Scope order.** `upcoming`: agreed time ascending (soonest first), then requests still waiting by the time asked for, then id. `past`: newest first.
- **Shortlist categories.** A worker with two categories counts once in each. Workers no longer visible have no category, appear only in the unfiltered list, and are not in `categoryCounts`. Not filtered in SQL: the shortlist is capped at 100 entries (MAX_SHORTLIST_ENTRIES), so the service reads those ids, resolves their categories with one SQL statement and slices the page in memory.
- **Pagination format** stays `{ data, meta: { page, limit, total } }`. `totalPages`, `hasNextPage` and `hasPreviousPage` were not added (no second convention); derive with `page * limit < total`.
- **Interview request eligibility** is unchanged and enforced only in `InterviewService.request` (server side).
